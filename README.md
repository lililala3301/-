# 灭建国（Forge 1.20.1）

作者：全民制作人

你是不是因为Minecraft世界不像现实世界一样拥有作弊码而感到苦恼？这款模组解决了你的烦恼，在聊天栏中发送50格内生物英文ID或中文名的首字，然后在接上“建国是谁的爸爸啊？”，生物就会破防大哭，然后飞速跑走，如果不知道生物的父母名字的话，可以尝试用9个下界合金块合成古明地觉fumo来实现开户操作。

在聊天栏发送 **50 格内某个生物英文 ID 或中文名的首字**，后面直接接上
`建国是谁的爸爸啊`（末尾可带 `？`），就会触发：

1. 以极高音量播放 `buhenimenwanle.mp3` 的音效；
2. 生物被强制转过身，背对玩家；
3. 以 **20 格/秒（1 格/tick）** 的速度远离玩家，并按地面 / 游泳 / 飞行三种方式适配移动；
4. 每跑 **6 格** 向上丢出一个水瓶（投掷型喷溅水瓶）；
5. 逃跑全程从头部两侧持续喷射水花粒子，粒子的尺寸与数量随生物体型缩放；
6. 跑出玩家有效可见距离后静默强制删除，**不再显示删除提示**；
7. 成功触发时，被触发的生物会在聊天栏喊出：
   `不和你们玩了！那是我爸的名字，我一会告老师！`

> 移动使用 1.20.1 中不可重写的 `Entity#setPosRaw` / `Entity#setBoundingBox` 写入，
> 并在每 tick 开始和结束各强制一次。`NoAI` 只负责辅助关闭 AI；即使某个生物重写了
> `setNoAi` 或 `setPos`，位置仍会被写回。

## 使用

触发格式（必须整条消息以触发语结尾）：

```text
<英文 ID 首字母或中文名首字>建国是谁的爸爸啊
```

| 目标 | 可用输入 | 说明 |
| --- | --- | --- |
| 苦力怕 | `苦建国是谁的爸爸啊` | 中文名首字 |
| 苦力怕 | `c建国是谁的爸爸啊` | 英文 ID `creeper` 的首字母 |
| 末影龙 | `末建国是谁的爸爸啊` / `e建国是谁的爸爸啊` | 中文首字 / 英文首字母 |
| 僵尸 | `僵建国是谁的爸爸啊` / `z建国是谁的爸爸啊` | 同首字有多个目标时，选最近的那个 |
| 其他模组生物 | 根据其注册 ID / 中文翻译名同样处理 | 中文名找不到时仍可用英文首字母 |

另外也接受完整的英文 ID（如 `minecraft:creeper`）或完整中文名，作为额外便利。
玩家不会被选为目标；盔甲架等 `LivingEntity` 可以被选中。

- 搜索半径：玩家周围 **50 格**。
- 同一首字匹配到多个生物时，只触发**距离玩家最近**的一个。
- 触发语会作为正常聊天显示，不会被拦截或隐藏。
- 50 格内没有匹配目标时，不再提示“50 格内未找到”，而是在聊天栏提示：
  `好像没人听到哦喵`。
- 成功触发时，目标生物会以自己的名字在聊天栏回一句：
  `不和你们玩了！那是我爸的名字，我一会告老师！`
- 目标已经在逃跑时，重复输入不会叠加速度，只会提示等待；也不会重复让生物喊话。

## 古明地觉fumo

新增物品 **古明地觉fumo**：

- 合成：3×3 摆满 **9 个下界合金块**（配方书会在获得下界合金块后解锁）。
- 物品介绍：`鼠标右键可以将附近的生物直接开户`。
- 右键使用（物品不会被消耗），聊天栏会提示：`觉大人完成了一次读心`。
- 以玩家为中心，给 **24 格内最多 32 个** 非玩家生物头顶显示读心标签，持续 **10 秒**。
- 标签格式：`爸爸：<首字>建国`。
  - 优先使用生物中文名的第一个字，例如苦力怕 → `爸爸：苦建国`。
  - 没有可用中文名时，回退到英文注册 ID 的第一个字母。
- 标签使用原版 `TextDisplay` 实体，自动跟随目标，字号由目标碰撞箱宽高决定：
  鸡这样的小生物标签较小，苦力怕中等，末影龙等大型生物更大。
- 再次右键会清除上一批标签后重新读心，不会无限堆叠。
- 标签是服务端生成的原版展示实体，不需要额外客户端渲染代码；使用告示牌式背景、始终面向玩家并忽略光照。

材质参考 [Gift 古明地觉 fumo 商品图](https://jhfigure.com/products/fumofumo-series-satori-komeiji-17cm-touhou-project-gift-plushie)，
重新绘制成 32×32 像素物品图标（不是直接裁切照片）。

## 逃跑与删除的实现

位置强制不再调用可被重写的 `Entity#setPos`，而是直接调用 1.20.1 中 **final** 的
`Entity#setPosRaw` 和 `Entity#setBoundingBox`。因此即使模组生物重写了 `setPos`、
`makeBoundingBox`、传送方法或 AI，也无法拒绝被移动。

每 tick 做两次强制：

1. **tick 开始**：在实体 AI 和实体追踪发包之前，把上一 tick 的强制位置重新写回；
2. **tick 结束**：在所有实体 tick 完成后，按逃跑路径推进 1 格。

路径始终从“本模组上一 tick 的强制位置”计算，而不是从生物当前坐标计算。这样 AI
或其它模组在 tick 中把生物往反方向拉，也不会带偏逃跑路线，下一 tick 仍从强制轨迹继续。

其它细节：

- 对 `Mob` 额外设置 `NoAI`、停止寻路、清除攻击目标。
- 设置 `invulnerable`、`noPhysics`、`noGravity`，清除着火并补满空气，防止它在演出途中被地形或其他生物打断。
- 手动推进 `walkDist`，避免直接写坐标导致生物滑行、腿不动。
- 按目标碰撞箱尺寸判断“体型”，用于水花粒子的 scale 和 count。
- 每 6 格生成一个向上投掷的 `ThrownPotion`（水），不是简单的掉落物。
- 到达有效可见边界时直接静默删除，不发送任何“已删除”消息。

### 非步行移动适配

- **地面 / 步行**：按地形高度平滑跟进，不依赖寻路。
- **水生**：`WATER_CREATURE`、`WATER_AMBIENT`、`AXOLOTLS`、`UNDERGROUND_WATER_CREATURE`
  以及 `WaterAnimal` 使用游泳路径。在水里时保持当前水深移动；被带出水面后会寻找附近
  的水面并回到水下；找不到水时贴着地形上方滑行，不会被强行按到地上“走路”。
- **飞行**：`EnderDragon`、凋灵、恶魂、幻翼、恼鬼、蝙蝠、蜜蜂、鹦鹉、悦灵等，以及
  `FlyingMob`、`FlyingAnimal` 和带悬浮标记的第三方生物，会按自身高度与地形保持飞行
  净空，末影龙不会贴地跑。没有实现飞行接口的第三方悬浮生物也有高度/重力回退判定。

删除时执行的是 1.20.1 中 **final** 的 `Entity#discard()`（其内部调用同样 final 的
`setRemoved`），因此普通模组无法通过重写这些方法拒绝删除。额外做三层保险：

1. 调用 `ServerChunkCache#removeEntity` 强制从服务端区块追踪器移除；
2. 向该维度所有玩家直接发送 `ClientboundRemoveEntitiesPacket`；
3. 记住该 UUID 一段时间（本局游戏内），如果有模组通过事件/自定义逻辑把同一个实体重新加回世界，会在 `EntityJoinLevelEvent` 和每 tick 的清理中再次删除。

异常退出（服务器关闭、触发者退出/换维度）时会恢复目标原来的
`NoAI`、无敌、重力、碰撞、冲刺、空气和着火状态，避免留下永久卡死的实体。
正常跑到有效可见边界时则直接删除，不做恢复，也不发送删除提示。

## 音效说明

Minecraft/Forge 的声音系统只解码 **Ogg Vorbis**，不能直接播放 `.mp3`。因此构建时把
你提供的 `buhenimenwanle.mp3` 转成了单声道 48 kHz OGG（时长 5.44 秒），以
`buhenimenwanle` 为注册名打包。播放使用 `SoundSource.MASTER`、音量 8.0，
不依赖音乐/唱片音量条。原始音频文件没有被修改。

## 安装 / 构建

- Minecraft：**1.20.1**
- Forge：**47.x**（构建目标 47.4.28）
- Java：**17**

构建好的模组文件：

```text
build/libs/miejieguo-1.20.1-1.4.0.jar
dist/miejieguo-1.20.1-1.4.0.jar
```

把它放进 `.minecraft/mods` 即可。客户端和服务端都需要安装。

从源码构建：

```bat
gradlew.bat build --offline
```

构建时需要 JDK 17。首次构建如果没有本地 ForgeGradle 缓存，可去掉 `--offline`。

## 边界说明

- “有效可见距离”取**服务端视距**与**该实体类型的追踪距离**中较小的一个。服务端
  视距决定区块是否下发，实体追踪距离决定客户端是否还能收到这个生物；超过其中任何
  一个，玩家都已经看不见它，因此在这个边界静默强制删除。单人游戏中服务端视距通常
  跟随客户端视距设置；原版生物的追踪距离常见为 8 区块（鱼等小型生物可能更短）。
- 生物外观尺寸用碰撞箱宽高作为服务端可获得的近似值。纯客户端渲染放大且碰撞箱不变的
  模组生物，会按碰撞箱计算。
- 对恶意到直接改写 JVM 字节码、或删掉实体后换一个新 UUID 重新生成的代码，任何普通
  模组都无法做绝对承诺；本模组覆盖的是 Forge 事件、实体重写、AI、无敌、OP 保护以及
  常规的重生/加回逻辑。
